# Changelog

## [1.20.0] - 2026-03-23

### Added

- Поддержка IPv6-маршрутизации
- Команда 'ip dhcp snooping action shutdown'
- Режим Port-Security sticky
- Опциональное отключение сообщения "Last login .." при логине ('set cli hello-prompt {on | off}')
- Команда для блокировки unknown multicast-трафика на адреса 239.0.0.0/8 при включенном IGMP Snooping на моделях SNR-S5210, SNR-S5110G-24TX(-POE)
- Остановка процесса ZTP при применении настроек в WEB
- SNMP OID для настройки flood control на портах (.1.3.6.1.4.1.40418.7.100.3.2.1.43, .1.3.6.1.4.1.40418.7.100.3.2.1.44, .1.3.6.1.4.1.40418.7.100.3.2.1.45 )
- SNMP OID для получения таблицы IP DHCP Snooping Binding (.1.3.6.1.4.1.40418.7.100.13.3.20)

### Changed

- В команде iperf3 диапазон значений TOS расширен с <0-7> до <0-255>

### Fixed

- Названия источников питания для моделей SNR-S5310X-8TX-DC и SNR-S5310X-8TX-UPS
- При настройке SNMP-сервера с нестандартным портом постоянно отправлялся Dying Gasp SNMP Trap
- Исправлен hostname по умолчанию для модели SNR-S5310G-48TX hw rev 2
- Negotiation на Fiber Combo-портах отключалось в режиме force1g-full
- Некорректная работа User-Defined ACL на моделях SNR-S531x, SNR-S5110G-48TX(-POE) (в ACL попадали пакеты с портов ge33-48 и xe, независимо от порта на который установлен ACL)
- При добавлении порта в режиме Hybrid в PO/SA удаляется VLAN 1 из списка разрешенных untag VLAN
- Лишние пробелы в running и startup конфигах
- В режиме 'no igmp snooping report-suppression' при получении IGMP Leave без опции Router-Alert в следующем IGMP Query пакете могли устанавливаться некорректные SRC_IP и DST_IP
- Отображение статуса вентиляторов SNR-S5210G-24FX в WEB
- При настройке IPv4, IPv6 или MAC ACL правила, отличающиеся только по VLAN или по DST Port, ошибочно интерпретировались как дублирующие (% This object already exist)
- Исправлена работа функционала 'archive running-config'
- В MAB не авторизовывались пакеты, если SMAC изучен на другом порту коммутатора
- SNMP: В OID dot1qVlanCurrentUntaggedPorts (1.3.6.1.2.1.17.7.1.4.2.1.5) и dot1qVlanCurrentEgressPorts (1.3.6.1.2.1.17.7.1.4.2.1.4) не отдавались Static-Channel интерфейсы
- Решены проблемы совместимости конфигурации SNMP при обновлении с версий ниже 1.17.0

### Fixed

- Утечка памяти при выполнении команды 'show running-config'
- Зависание коммутатора при вызове команды 'show ip dhcp binding' в определенных сценариях
- Некорректное время в выводе команды 'show ip dhcp snooping blocked'
- Некорректные индексы агрегированных портов в OID dot1qTpFdbPort (1.3.6.1.2.1.17.7.1.2.2.1.2 )
- Ошибка 'OID not increasing' при одновременном опросе OID dot1qTpFdbPort (.1.3.6.1.2.1.17.7.1.2.2.1.2) и dot1dTpFdbAddress (.1.3.6.1.2.1.17.4.3.1.1)


## [1.18.0] - 2025-12-05

### Added

- SNMP: Добавлена ветка для управления функционалом ERPS erpsMgt (.1.3.6.1.4.1.40418.7.100.39)
- Добавлено шифрование паролей FTP, SFTP и SCP в команде 'archive running-config' при выводе конфигурации
- Логирование событий функционала 'ip dhcp snooping action blackhole'
- На оптических портах добавлен механизм Port-flap Errdisable, для исключения зависания ПО при большом количестве link-flap. Errdisable срабатывает при смене состояния порта более 10 раз в течение 5 секунд. Таймаут восстановления порта - 30 сек.
- Поддержка модели SNR-S5210G-24TX-R

### Changed

- Команда 'ip dhcp snooping binding user-control' разрешена на trunk и hybrid портах
- Добавлен фильтр кириллицы в логине и пароле и отображение количества введенных символов в пароле
- Добавлена обработка IGMP пакетов с IP-адресом назначения 224.0.0.0/23 функционалом multicast destination control
- Оптимизирована работа SNMP ветки POE на моделях SNR-S5110G-24TX-POE и SNR-S5110G-48TX-POE
- OpenSSH обновлен до версии 10.2p1. Дополнительно разрешены алгоритмы KEX: diffie-hellman-group1-sha1, diffie-hellman-group14-sha1, diffie-hellman-group-exchange-sha1, ciphers: aes128-cbc, aes192-cbc, aes256-cbc,3des-cbc, MAC: hmac-sha1, hmac-md5, hmac-sha1-96, hmac-md5-96, host и public ключи ssh-rsa

### Fixed

- Некорректное отображение статистики пакетов ACL
- Постоянная отправка SNMP Trap Dying Gasp при использовании нестандартного SNMP порта
- При включенном PPPoE Intermediate Agent PADR пакеты, полученные на trust порт, копировались обратно в этот же порт
- MSTP: некорректное отображение Designated Bridge в команде 'show spanning-tree mst instance'
- MSTP: неверный Bridge ID в пересылаемых BPDU
- RSTP: исправлена работа алгоритма Proposal-Agreement
- Ложное срабатывание storm-control при ограничении <= 10 pps на моделях SNR-S5110G-24TX(-POE), SNR-S5210
- SNMP: OID ifAdminStatus некорректно выключал интерфейс
- SNMP: OID shutdown (.1.3.6.1.4.1.40418.7.100.3.2.1.12) не восстанавливал интерфейс из состояния Errdisable
- SNMP: скорректировано значение OID ifSpeed для портов 10GbE


## [1.17.0] - 2025-09-15

### Added
- DHCP Snooping Binding user-control в VLAN
- Gratuitous ARP
- User-defined ACL
- Шаблоны vendor и model в команде 'ip dhcp client vendor-identifier'
- Поддержка SHA-256 в шифровании паролей пользователей SNMPv3
- Логирование функционала 'spanning-tree guard root'
- SNMP OID на получение VLAN MAC коммутатора (1.3.6.1.4.1.40418.7.100.1.105.0)
- В SNMP OID sysName (1.3.6.1.2.1.1.5.0) добавлена возможность записи
- Поддержка модели SNR-S5310X-8TX
- Поддержка модели SNR-S5310G-48TX hardware version 2.x

### Changed
- Настройки SNMP выделены в отдельный режим конфигурации SNMP (сохранена совместимость с предыдущей конфигурацией)
- Одновременная перемаркировка и приоритезация трафика по полям DSCP и COS в Policy-map
- Оптимизирована работа автосогласования на SFP+ портах для совместимости с 1G SFP трансиверами сторонних вендоров
- Отключено хранение ключей (known hosts) в SSH клиенте
- Оптимизирован опрос параметров PoE в CLI и SNMP на моделях SNR-S5110G-24TX-POE и SNR-S5110G-48TX-POE
- SNMP Engine-ID приведен к виду 8000DF7603 + CPU MAC коммутатора

### Fixed
- Перезагрузка при записи пустой строки в некоторые SNMP OID
- Совместимость 802.1x c сервером Windows NPS
- Неверное расположение настроек ACL относительно class-map в конфигурации, что приводило к некорректному применению startup-config
- Скорректировано поведение DHCP Snooping Binding для записей с одинаковыми MAC и IP
- При применении команды 'no hostname' удалялся lldp system-name
- Скорректирована работа команды 'spanning-tree guard root' (состояние root-inconsistent на портах в DOWN, таймер восстановления)
- Обновление ARP записи при смене MAC
- Исправлено значение SNMP OID ifSpeed (1.3.6.1.2.1.2.2.1.5) на 0 для SFP+ портов в состоянии DOWN
- Из счетчика input error на интерфейсе исключены pause frame
- Исправлено отображение команды 'snmp-server host <host> {informs version 3 | traps version 3 | version 3 } priv' в конфигурации
- Невозможность использования спецсимволов '~ }{ & > < % ! + , ' в команде 'copy ..' в username и password

### Fixed

- В определенных сценариях после удаления RADIUS сервера на него продолжали отправляться запросы авторизации
- Не удалялась команда 'ip dhcp snooping binding user-control' с интерфейса, если на нем есть запись AM
- ERPS: исправлена некорректная очистка MAC-адресов при получении R-APS (SF) пакетов в состоянии Protection
- При удалении Multicast VLAN на портах, где он был ассоциирован, удалялся пользовательский VLAN
- Флап линка при первом включении LLDP на порту
- Номера OID в ветке poePortConfigEntry (.1.3.6.1.4.1.40418.7.100.26.10.1) приведены в соответствие с MIB
